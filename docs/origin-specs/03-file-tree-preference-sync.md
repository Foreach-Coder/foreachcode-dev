## 1. 需求背景

会话侧边栏可能先于持久化设置完成初始化。若只在布局创建时读取一次“显示文件树”偏好，设置恢复完成后或用户运行时切换偏好时，界面不会随之更新。

该偏好在首次恢复和运行时修改时具有不同语义：首次恢复为关闭时保留当前版本提供的初始布局；用户在设置就绪后主动关闭时，必须立即关闭文件树。

## 2. 行为合同

| 状态                     | 要求                                         |
| ------------------------ | -------------------------------------------- |
| 设置尚未恢复             | 不改变当前布局，不能把临时默认值当作用户偏好 |
| 首次恢复为启用           | 主动打开文件树，以补偿界面早于设置初始化     |
| 首次恢复为关闭           | 不主动关闭，保留目标版本既有的会话初始布局   |
| 设置就绪后由关闭变为启用 | 打开文件树                                   |
| 设置就绪后由启用变为关闭 | 关闭文件树                                   |
| 值未变化或重复通知       | 不执行重复动作                               |

组件重新挂载时，如果设置已经就绪且偏好为启用，文件树必须重新打开；偏好为关闭时仍保留该次挂载的初始布局，直到用户发生一次真实偏好切换。

## 3. 约束

- 同步过程不能回写偏好，避免形成布局与设置之间的反馈循环。
- 不改变窄屏断点、review panel、文件 tab、拖拽尺寸和文件树显示条件等既有布局规则。
- 多次相同通知必须幂等。
- 版本实现必须明确区分“设置未恢复”和“设置已恢复且值为关闭”。

## 4. 非目标

- 不重新设计会话侧边栏或文件树布局。
- 不定义首次恢复为关闭时新的统一默认布局。
- 不改变偏好的持久化格式或作用域。

## 5. 验收标准

1. 设置未恢复时，文件树不会因临时默认值打开或关闭。
2. 首次恢复为启用时恰好打开一次；首次恢复为关闭时不强制关闭。
3. 设置就绪后的启用和关闭切换分别恰好触发一次对应动作。
4. 重复相同值不产生动作。
5. 组件重挂载遵守首次恢复规则。
6. review panel、文件 tab、响应式布局和文件树原有显示条件不受影响。
