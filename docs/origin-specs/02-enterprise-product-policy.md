## 1. 需求目标

BluedCode 企业发行必须默认拒绝由产品自身发起的公共服务连接，并把模型 Provider 的建立权交给管理员维护的静态配置。安全限制必须在最内层服务边界生效，隐藏界面只能作为辅助防线。

企业策略属于静态产品 Profile 中的不可变产品属性，不能被普通用户、运行时环境变量或客户端状态关闭。

从 OpenCode 1.18.18 起，Provider、凭据、配置写入、分享、更新和公共网络能力必须在源码服务边界实现。构建层只负责装配、静态入口处理与最终审计；构建期 AST 替换不得作为企业安全边界。

## 2. Provider 管控

- 只允许加载管理员在产品配置中显式声明的 Provider。
- Provider、模型、MCP、插件、远程配置和其他可能产生外联的集成能力只能由管理员静态配置；普通用户不能通过项目配置、环境变量、GUI 或 API 新增、修改或认证这些能力。
- 环境变量、全局凭据、账户组织、well-known token、插件认证 hook 和内建自动发现不得使未声明 Provider 出现。
- 管理员仍可为已声明 Provider 配置模型、服务地址、API key 和其他必要选项。
- 普通用户不能通过 UI、CLI、HTTP API、OAuth 回调或遗留入口新增或写入 Provider 凭据。
- 删除历史凭据可以保留，但被删除前的凭据也不得参与 Provider 加载。
- Provider 和模型列表只显示管理员配置后实际可用的结果，不混入公共目录或连接引导。

## 3. 用户界面

企业发行不得展示连接或新增 Provider 的入口，包括设置页、命令、模型选择器按钮、自定义 Provider 对话框和首次使用引导。

模型管理和模型选择仍然可用，但只能操作管理员已经配置并由服务端返回的模型。客户端绕过隐藏控件时，服务端仍必须拒绝受限操作。

主题、语言、字体、快捷键、通知、V1/V2 布局和其他不产生网络或信息外发的本地偏好必须继续支持图形化配置。前端应通过统一的产品 UI 注册表决定页面和操作是否注册，不得依赖在大量按钮和页面中重复散布产品条件。

## 4. 配置边界

配置必须分为两条互不混用的通道：

- 管理员静态配置负责 Provider、model、MCP、插件、远程地址、凭据引用和其他外联集成；
- 用户本地偏好负责纯本地界面与行为设置，并通过显式 schema allowlist 写入 Desktop 本地状态。

所有用户配置写入必须经过同一个配置变更策略。未分类的新字段默认拒绝写入；已明确属于本地偏好的字段允许图形化修改。GUI 不得提交或回写完整管理员配置对象。

项目目录配置可以继续控制已批准的纯本地项目行为，但其中的 Provider、model、MCP、插件、远程配置和凭据字段不得进入运行时集成注册表。

## 5. 模型目录

- 运行时不得下载或定时刷新公共模型目录。
- 可以读取可信的本地缓存或随构建提供的离线模型快照。
- 缺少有效离线数据时必须返回安全的空结果或在发布构建前失败，不能回退到公共网络。
- 用户显式要求刷新时也不得绕过该限制。

## 6. 会话分享

- 本地会话不得被发布为公开分享链接，也不得自动分享。
- 即使配置了服务地址，分享创建和发布仍必须在服务边界失败且不发送请求，直到另有企业内部分享规格。
- Desktop、Web、CLI 和 TUI 不提供 share、unshare 或公开链接入口。
- 从用户明确提供的外部分享 URL 导入公开数据可以保留，但不得上传本地会话、代码或凭据。

## 7. 遥测与诊断

- 企业发行不得因环境继承而创建远程日志或 trace exporter。
- 创建子进程、隔离 workspace 或 adapter 时不得转发公共遥测配置和凭据。
- 发布构建必须清除 Sentry 或其他远程诊断凭据。
- 本地文件日志继续可用，`ORIGIN-06` 定义的 LLM 性能信息只能进入当前明确配置的本地日志链路。
- 若未来接入企业内部遥测，必须另写需求，明确可信 endpoint、凭据来源、字段白名单和管理员开关。

## 8. 更新及其他公共能力

- Desktop、CLI 和 server 不得检查、下载或安装公共更新。
- UI 不展示检查更新入口，直接调用遗留入口也必须安全失败。
- 默认不注册公共 Console、上游 changelog、反馈和 GitHub Agent 等产品入口。
- 未内嵌 Web UI 时不得代理到上游公共 Web 应用。
- 可以保留更新和安装抽象，以便未来实现企业内部更新源。

## 9. 根服务与 Fail-closed 合同

企业能力必须收口到少数天然根边界：配置变更策略、管理员集成快照、Provider/MCP/插件注册表，以及分享、目录、遥测、更新和公共代理服务。HTTP handler、IPC 和 UI 控件不得各自重新实现同一安全策略。

产品 Profile 必须声明稳定操作矩阵，运行时授权、UI surface、构建 manifest 和最终审计都从该矩阵派生，不得再维护一份独立的 EnterprisePolicy 布尔值集合。

当策略缺失、配置无效、内部服务未接入、客户端状态陈旧或旧入口被直接调用时，系统必须拒绝受限操作，并满足：

- 拒绝发生在网络请求和状态写入之前；
- 不产生部分配置、凭据或会话状态；
- 错误稳定、可识别，但不泄露凭据或请求内容；
- UI 隐藏失败不影响服务边界的安全性。

服务边界拒绝必须使用稳定的产品错误码，使 UI、HTTP API、直接服务调用和诊断日志能够区分预期策略拒绝与意外程序错误。

## 10. 非目标

- 不阻止管理员静态配置中明确批准的 Provider、MCP server、插件、LSP、工具请求或其他业务连接。
- 不定义企业内部 Provider 分发、更新、分享、遥测或凭据服务。
- 不要求删除上游实现，只要求企业发行默认无法触发受限能力。
- 不把企业限制永久施加到非企业发行。

## 11. 验收标准

1. 注入环境 Provider key、全局凭据或账户信息后，未显式声明的 Provider 仍不可见且不可用。
2. 管理员显式配置的 Provider 和模型可以正常选择和调用。
3. 所有凭据写入、Provider/MCP/插件连接和外联集成配置变更均失败，且没有持久化或网络副作用；已批准的本地偏好仍可通过 GUI 修改并持久化。
4. 公共模型目录、分享、遥测和更新在启动及用户操作期间均产生零公共请求。
5. UI 中不存在受限入口，绕过 UI 直接调用服务也会失败。
6. 本地日志继续工作，但子进程不继承公共遥测配置。
7. 入站分享导入不会携带本地数据向外发送。
8. 非企业发行的上游能力不因该策略被全局删除。
9. HTTP、IPC、旧客户端或内部直接调用绕过 UI 时，仍只能到达同一个根服务策略；新增上游入口不能绕过管理员集成快照和副作用服务。
